# Deploy ClassLens with a Render Blueprint

**Made by Harshad Madhav Dhuppe — Electronics & Computer Engineering, Batch of 2027.**

The root [`render.yaml`](../render.yaml) defines one free Docker web service. The
compiled React interface and FastAPI API run together on the same HTTPS origin.
No separate frontend service, manual build command, CORS change, or additional
environment-variable entry is required for this demonstration.

## Create the Blueprint Instance

1. Sign in to [Render](https://dashboard.render.com/) and select the intended
   workspace. For this project, select **My Workspace**.
2. Choose **New → Blueprint**, connect GitHub if requested, and select
   [`Harshad8623/Vision-Based-Attendance-System`](https://github.com/Harshad8623/Vision-Based-Attendance-System).
3. Use branch **main** and Blueprint file **render.yaml** at the repository root.
4. Give the Blueprint a name such as **ClassLens**. Confirm the selected workspace
   and review the resource preview: one **Free** web service named
   **classlens-attendance**, with no database service or paid disk.
5. Choose **Deploy Blueprint** or **Apply**, according to the wording in the
   Render dashboard. Render builds the Docker image and starts the service.
6. When the service is live, open the HTTPS URL Render assigns to it. The final
   hostname is assigned by Render and should not be assumed in advance.

You can also start from this repository's
[Deploy to Render link](https://render.com/deploy?repo=https://github.com/Harshad8623/Vision-Based-Attendance-System).
Select the workspace during Render's deployment flow; the link does not create a
service or select a workspace by itself.

## What the Blueprint configures

| Setting | Behaviour |
| --- | --- |
| Docker image | Multi-stage build from the existing Dockerfile |
| Plan | Free demonstration instance |
| Startup | Verify/download official face models, then start Uvicorn on Render's `PORT` |
| Model cache | `/tmp/classlens/models`, writable by the non-root application user |
| Application data | `/tmp/classlens/data`, containing the SQLite database |
| Session secret | Random value generated by Render; never committed to Git |
| Health check | `/api/health` |

Models are downloaded at service startup, not during the image build. The
downloader preserves TLS and checks the pinned sizes and SHA-256 hashes. An
already verified cached model is reused while that cache exists. A failed
download stops startup rather than allowing fabricated recognition results.

The startup command is `python -m backend.start`. Model setup and port selection
run in Python, so the platform does not need to interpret nested shell quotes.
The Docker image uses the same default command.

### Update an earlier deployment

If an earlier deployment failed with `/bin/sh: ... not found` and exit code 127,
sync the Blueprint to the latest commit on `main`. Confirm the service's Docker
Command is exactly:

```text
python -m backend.start
```

If you previously entered a manual Docker Command in the service settings,
replace it with the command above, save, and deploy the latest commit. The failed
quoted `/bin/sh -c ...` override must not remain. No change to secrets or a paid
plan is required for this startup correction.

## Check the deployment

Open `/api/health` on the assigned service URL. Expect:

```json
{
  "status": "ok",
  "database": "connected",
  "vision_ready": true,
  "demo": true
}
```

Use the demonstration accounts documented in the [README](../README.md#demonstration-accounts).
On a phone, open the HTTPS URL and allow camera access. Enroll consented samples
before testing recognition; fictional seeded students have no face templates.

If deployment fails, inspect the service's **Logs**. In particular:

- Build errors occur before startup; check the Docker build log first.
- Model download failures require outbound HTTPS access to
  `media.githubusercontent.com`; do not disable TLS or checksum verification.
- The server must bind `0.0.0.0` using Render's `PORT`. The Blueprint command
  already does this.
- If `vision_ready` is false, check that this Blueprint's model directory and
  startup command are applied to the service.
- If a service already exists, the Blueprint may create an additional service;
  review the proposed resources before applying. This configuration does not
  automatically migrate or delete an earlier deployment.

## Demonstration limits

The free service uses ephemeral storage. Attendance, account changes, leave
requests, and face enrollments can disappear when an instance is replaced or
redeployed. Model files must also download again after replacement. Free
instances can sleep, and CPU/memory limits can affect recognition speed.

Public demo credentials remain intentionally available in this version. Use
fictional records for a public demonstration. Before a real institutional pilot,
replace those accounts, add account/password management, configure durable
storage and backups, and evaluate recognition on consented classroom data.

A paid persistent disk or database migration is a separate deployment change.
For a disk, its directories must be writable by the application's UID `10001`;
the image's existing directory ownership does not establish ownership of a new
mount. This Blueprint does not provision paid resources.

Adding `render.yaml` to GitHub makes the repository deployable with a Blueprint;
it does not create the Render instance. Render creates it when you apply the
Blueprint in your selected workspace.
